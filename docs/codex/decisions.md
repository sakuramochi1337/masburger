# 改良方針（Claude × Codex で合意したこと）2026-11-12

詳細は round1/reply1、round2/reply2。

## 実測（改修前）
- 公開 emqx 経由：子の操作がホストに確定するまで p50 10秒・p95 14〜19秒。ホスト→子 片道 p50 7.8秒、最大45秒。子の操作の半分以上がホストに届かない。
- 公開 emqx は 1接続あたり約10通/秒を超えると黙って捨てる。ゲームは25〜30通/秒送っていた。retain の古い状態が再接続時に届き、巻き戻っていた。
- 子だけに 250〜280ms のヒッチ（古い/新しいスナップショットの交互適用による置き物の大量再構築）。

## 決めたこと
| 項目 | 決定 | 理由 |
|---|---|---|
| 通信路 | WebRTC DataChannel の**メッシュ**（Codex は当初スター型を推奨→ round2 で合意） | 最大4〜6人。店長交代時に張り直しの断絶が出ない。presence 同期をそのまま載せられる |
| シグナリング | 既存の公開 MQTT。非トリクル ICE で offer/answer 各1通 | 流量制限に当たらない |
| フォールバック | P2P が健全でない相手がいる時だけ MQTT。1通にまとめて最大8通/秒、retain 無し、2秒ごとに全キー | 公開ブローカーの上限内 |
| 経路の切替 | 送信者ごとの通し番号を両経路共通で付け、古い番号は捨てる。P2P は「open かつ3.5秒以内に受信あり」で健全とみなし、崩れたら MQTT で全キーを送り直す | Codex 指摘：open だけでは詰まりを見抜けない |
| epoch | ホストの peer ID＋その peer の就任回数。子は「今のホストの今の epoch」の番号だけを比べる | 時刻ベースはPC間の時計ずれで新ホストを拒否しうる（Codex 案から変更） |
| 操作 | リング6→24件、ack 済みは送らない。初見の相手の未処理操作も実行（L1989 のバグ、Codex 指摘）。新ホストは旧ホストの ack を引き継ぐ | 操作の永久消失を防ぐ |
| 予測 | pend は ack ベース＋保険4秒。完全な再適用（ロールバック）は見送り | P2P なら ack は数十ms |
| 子側の時間 | 描画用だけローカルで進め、権威値は毎回ホストで上書き | Codex 指摘の境界 |
| 裏タブ | Worker の時計で進行と送信を回す。ホストが裏タブでも営業は止めない | Chrome は裏タブのタイマーを1Hz以下に絞る |
| 再構築 | box/cyl ジオメトリをキャッシュ、所有リソースだけ dispose、ラベルは使い回し。DOM は変化時だけ | ヒッチとリーク |
| 客 | Kenney Mini Characters（CC0）。アニメは1ファイルを共有 | 箱人間の置き換え |
| ゲーム性 | **D1 段ボール配送**だけ入れる。箱は裏口の床を占有して通路の邪魔になる／補充するまで在庫に入らない。納品遅延は入れない | SM/FF Simulator らしさに一番効き、協力の役割分担が生まれる（Codex と一致） |

## 見送り（次の候補）
- D2 片付け、D3 価格設定、D4 ランク/ライセンス
- 予測の完全な再適用、ホスト交代時の完全なスナップショット検証（いまは becomeHost で復元できる分だけ）
- TURN サーバー（張れない組は MQTT で補う）

## D2 片付け（Round 3、2026-11-12）
| Codex の指摘 | 対応 |
|---|---|
| 「汚い」で30%引き返すと負の連鎖 | 10%に下げ、汚れ8点以上（実効）のときだけ |
| 効果が重なると原因が分からない | HUD に「店内 汚れ気味 ・ 我慢−12% チップ−30%」と今の影響を常時表示 |
| 閾値方式だと「閾値まで放置」が最適になる | 2つ目の汚れから少しずつ効く連続式（我慢 −2.5%/点・下限75%、チップ −6%/点・下限40%）。口コミの格下げも汚れに比例した確率 |
| 返却口の効果が見えない | 発注端末と日報に「今日 返却 n/m 人」 |
| ノーマル/イージーの店内飲食は後回しに | **不採用**：入れないとノーマルでは片付けがほぼ床のゴミだけになり、料理か片付けかの判断が生まれないため。代わりにホスト＋子の自動プレイで同期を確認（イージーは効果半分・発生率低め） |
